# DeepSeek Harness Community Promotion Research

This note records the first-party sources used to shape the Neonforge community announcement. It focuses on publication structure, not endorsement of any third-party project.

## Observed publication pattern

Official DeepSeek Harness community posts make the project legible quickly: state what was built, explain the user problem, list concrete capabilities, show the project URL and screenshots, provide a copyable installation command, describe how the project integrates with DSH, and end with specific questions for feedback.

The `Show Your Plugins!` category is the natural destination for a plugin announcement. Its guidance requires a clear project URL, a short introduction, screenshots, and an explanation of how the project integrates with DSH. Third-party projects must be labeled unofficial, and authors should not imply DeepSeek review or endorsement.

## Application to Neonforge

Neonforge should be presented as an independent DSH Web visual skin, not as a replacement Agent, an official DeepSeek theme, or a runtime fork. The strongest claim is that it keeps DSH behavior and changes the workbench presentation through plugin and theme extension points.

The post should put the visual result near the top, follow it with the shortest npm installation path, then explain the non-goals and compatibility limits. Specific feedback questions about readability, theme preference, status visibility, and version compatibility are more useful than a generic request for stars.
