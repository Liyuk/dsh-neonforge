# Boujoy Harness 设计语言参考

[English](boujoy-harness-design-analysis.md) | 中文

## 范围与证据

本文记录对 [Boujoy Harness](https://github.com/asen-goat-mine/boujoy-harness) 视觉系统的分析，依据为分析时该项目公开仓库中的内容。本文是为 Neonforge 工作台准备的设计研究资料，不表示任何关联，也不授权复用 Boujoy 的代码、名称、标志、图像或字体文件。

证据包括公开的 `web/index.html`、`web/app.css`、随仓库提供的图像资源，以及 Agent 页面和知识库页面的桌面渲染。标记为「已观察」的精确值和组件行为均来自这些来源。标题为「适配建议」的章节是面向 DSH 实现的推导，不得视为 Boujoy 的产品要求。

Boujoy 是围绕 DeepSeek Harness、本地网关和 Markdown Vault 构建的本地桌面宿主。界面必须呈现正在进行的对话、累积的项目上下文、agent 执行状态、审批、文件和可选的知识工具，同时不能让本地工具看起来像普通的管理后台。它以视觉方式兑现这一承诺：把 agent 任务表现为可亲手掌控的生产工作，而不是不可见的云端自动化。

## 设计解读

**模式：**Operate。操作者必须快速发送任务、检查流式工作、处理一次中断，并回到先前上下文。信息可扫读性和清晰的状态变化比品牌奇观更重要。

**创意北极星：**本地朋克印刷工坊与实时工程控制台的结合。系统借用丝网印刷、胶带海报、套印、zine 和终端标签的材质语言，再把它们用于 agent 工作台。

**推荐命名：**后朋克、zine 拼贴式的赛博控制台。它拥有赛博朋克的输入：深色底、荧光酸绿、电蓝、洋红、终端标签和实时信号；但避开了这一类型惯用的紫蓝渐变、玻璃面板、城市夜景和柔和灯管光晕。这里的荧光是高饱和不透明油墨，不是发光体。

**情绪语气：**自信、独立、具备实体感、local-first，并略带挑衅。它避开柔和的 AI 产品语言，强调用户拥有工作区，能检查工作，而不是只向远端黑箱发出提示词。

**密度特征：**Agent 页面具有高功能密度，知识库与集合页面具有中等密度，首次引导和空状态则刻意降低密度。桌面端的装饰密度也较高，但移动端会明显收敛。

**主要对比：**产品以近黑色舞台和浅色文字为基础。酸性黄绿色是主要操作与焦点信号。蓝色和洋红构成丝网印刷的套印组合。青色和黄色提供额外的语义或编辑性对比。这个配色不应理解为泛化的「AI 霓虹」：硬边、不透明填充、像素字体和暖白色纸张感，使它更接近印刷短篇和电子设备标签。

## 视觉语法

### 构图

桌面端使用固定左侧导航轨、固定高度顶栏和按页面变化的内容框架。Agent 页面是三栏工作台：左侧为项目与会话上下文，中间为任务对话和输入器，右侧为实时运行信号。默认 CSS 中外层导航轨宽度为 166px，顶栏高度为 72px。Agent 页面以 238px 和 250px 的侧栏包围一个可伸缩的中间列。

该结构建立了稳定的阅读顺序：选择上下文、执行工作、检查结果。中间列拥有最高对比度和最多垂直空间。侧栏并非可互换的卡片，它们是职责不同的持续工作区。

其他页面会改变空间模型，但不放弃品牌。知识库采用宽大的编辑式页头、指标、搜索与筛选，随后是聚焦项目/下一步行动的分栏和卡片库。专家和风格采用集合布局。监控采用紧凑指标与轨迹列表。新闻采用编辑式信息流卡片。这种变化避免把每项功能都做成另一个仪表板标签页。

### 材质感

系统避免柔和的 SaaS 环境式浮层。它使用不透明或接近不透明的面板、1px 和 2px 边框、切角、无模糊的硬阴影，以及少量轻微旋转。这些选择暗示纸张、胶带、丝网印刷和机械套印。

重复出现的硬阴影偏移通常为 3px 至 8px，且常用蓝色或洋红而非黑色。选中或主要对象像被压在偏移的印刷层上。较大模糊仅用于克制的背景玻璃效果或移动端输入器，不是核心视觉特征。

### 装饰

装饰是结构性的而不是插画性的：点阵纹理、拼贴背景、几何碎片、倾斜标签、边缘裁切、低不透明度的大号数字，以及类似「MAKE / BREAK / BUILD」的旋转条带。它为标准控件建立连续的视觉世界。

这一系统有效的前提是装饰位于内容后方，并从属于文本和操作。当每个列表行或状态都同时拥有独立亮色、旋转、阴影和标签时，视觉语言会变得嘈杂。对于 DSH 适配，每个视口应有装饰预算：一个大背景场、一条边缘标签或碎片、一个信号处理已足够覆盖工作页面。

浅色模式会替换 panel、panel-solid、text、muted 和 divider 的值，同时保留高饱和强调色家族。这是实际的主题转换，不是简单反色。

### 从用法推导的颜色规则

- Acid 是主要操作色。它应出现于推进工作、激活导航或可见键盘焦点的控件，不应成为泛用卡片填充色。
- Blue 是结构性的偏移色。它让层级看起来像印刷套版。它最适合位于操作对象或选中对象之后，而非作为第二种默认按钮色。
- Pink 在源码中承担两项职责：危险/等待状态与视觉反衬。适配时必须先保留危险含义，只在语义冲突可接受时用于装饰。
- Cyan 是最好的正向状态信号，因为它与 Acid 的视觉区分清晰。应把它用于连接、完成或已附加上下文，而不是任意分类标签。
- Yellow 用于把知识与选中会话从主操作系统中区分出来。应限制其用量，以免与 Acid 竞争。
- 深色表面必须带色调，而非纯黑。纸张色必须偏暖，而非纯白。这样能保留深度，也能避免霓虹强调色与表面脱节。

### 字体排印

| 角色 | 已观察字体栈 | 常见字号与处理 | 职责 |
| --- | --- | --- | --- |
| 展示字体 | `Arial Black`、`Impact`、`PingFang SC`、sans-serif | Agent 视图中为 17px 至 27px；页面 hero 使用 `clamp(40px, 5vw, 60px)` | 强势的中文标题与关键操作。 |
| 阅读字体 | `Inter`、`SF Pro Display`、`PingFang SC`、`Microsoft YaHei`、sans-serif | 10px 至 13px，1.55 至 1.75 行高 | 对话内容、辅助文案、字段。 |
| 等宽字体 | `SFMono-Regular`、`Menlo`、`Monaco`、`Courier New`、monospace | 通常为 7px 至 10px，高字重与高字距 | 操作标签、时间戳、指标、状态。 |
| 像素字体 | 自托管 `FusionPixel`，以 `PingFang SC` 回退 | 导航中为 9px 至 20px；页面标题为 40px 至 60px | 品牌识别、导航、页面 hero、印刷工坊气质。 |

系统的个性来自字体角色之间的对比，而非堆叠装饰字体。像素展示字体让名称和中文标题如同印刷游戏标签。等宽字体标记操作与机器状态。阅读字体足够安静，能够承受流式消息。

**适配建议：**保留三角色模型，但提高关键信息的最小字号。在 DSH 工作台中，操作标签通常不应小于 11px，元数据不应小于 10px，用户/agent 正文不应小于 13px。将像素字体限制在导航、页面级标题和少数高显著性标签中；它不适用于密集系统控件或长文本。

### 间距、几何与深度

已观察到的间距集中在 4px、7px、8px、9px、10px、12px、14px、16px、20px、22px、24px、32px 和 48px。源码没有公开完整的间距刻度，但重复节奏近似于以 4px 为基础的系统，并为印刷标签保留有意紧凑的例外。

默认形状是锐利的。多个组件使用带有小对角裁切的 `clip-path` 多边形；旋转通常控制在约 0.2 至 5 度之内。圆形状态点和关闭按钮是例外，因为它们标识字面状态或直接操作控件。桌面系统几乎不使用通用圆角矩形。

硬阴影使用零模糊的不透明偏移。主裁切按钮使用 4px 蓝色偏移；大型 Agent 空状态使用 10px 偏移；消息卡片使用 4px 蓝色偏移。悬停状态通常会缩小偏移并让对象平移 1 至 4px，形成实体按压反馈。

**适配建议：**在广泛应用此语言前先引入显式刻度。

| Token 家族 | 建议的 DSH 刻度 | 用途 |
| --- | --- | --- |
| 间距 | 4、8、12、16、24、32、48、64px | 控件内边距、面板节奏、区块间距。 |
| 切角 | 0、4、8、12px 对角裁切深度 | 仅用于主要操作、选中导航、关键卡片和编辑式模块。 |
| 旋转 | 0、±0.5、±1、±2 度 | 应用于贴纸、印章和选中对象。绝不旋转密集列表或消息正文。 |
| 硬阴影 | 2、4、8px 零模糊偏移 | 仅为可操作、选中或重要对象保留。 |
| 边框 | 1px 结构、2px 交互、3px 特殊对象 | 避免为每个容器使用粗边框。 |

## 组件语言

### 应用外壳与导航轨

导航轨是深色视觉锚点，包含点阵纹理、带框的「B」标志、像素字标、六个编号页面入口、模式开关和设置。激活导航使用高对比切角票券，并延伸至导航轨边缘之外。每个入口都保留页面编号、英文操作标签和中文说明。

激活状态结合文字颜色、填充、横向位移、旋转、裁切和硬阴影。它不只依赖颜色。这是值得保留的强模式，因为即使色彩感知受限，用户也能通过形状和位置识别当前页面。

### Agent 工作台

Agent 页面有短身份行、可选思考条、可滚动消息流和底部输入器。assistant 消息是带蓝色硬阴影的深色描边块。用户消息是带洋红偏移阴影、略带裁切的黄色便签。该方向让作者身份一眼可辨，而不退回到常规聊天气泡。

中间面板的视觉层级是正确的：相对于明亮的导航和命令控件，内容平静且可读。工具摘要、完成步骤数和 token 数值属于从属等宽元数据。流式光标和状态标签使实时工作可观察。

**适配建议：**不要把每条 DSH 消息或工具结果都转换成装饰卡片。应保留这种区分：正文以内容为先；工具执行是紧凑的结构化证据；审批、中断和错误才使用更强容器。中间 transcript 必须是密集屏幕里最安静的部分。

### 输入器

桌面输入器是切角深色块，带荧光发送按钮、图像控件、权限与预设选择器、模型选择器、忙碌时的排队/引导模式，以及附件标签。焦点边框和替换为洋红的阴影会清晰标示当前可写位置。

在手机屏幕上，源码有意放弃桌面的裁切和硬阴影。输入器变为粘性、圆角、轻微磨砂的形态，文字增加到 16px，触控控件变大。这是一条重要规则：设计语言应适应实体交互界面，而不是把桌面装饰强加于触屏输入。

### 状态与信号

语义 LED 点出现在服务连接、agent 运行状态、待处理工作和选中状态中。圆点会与「LOCAL ENGINE · 已连接」和「待命」等文字配对，而不是单独承载状态。运行使用 Acid，在线使用 Cyan，错误与等待使用 Pink，空闲点使用弱化色。

运行时检查器以黄色信号卡显示当前目标、紧凑计划、工具记录、队列和 subagent。这让可观察性保持可见，又不会转移到主对话中。对于 agent 工作台，这种模式很有用：操作细节足够靠近，但不打断阅读。

### 知识库页面

知识模式从 Agent 页的紧凑操作布局转向编辑式场域。它使用大号像素展示标题、带蓝/粉偏移阴影的对比词处理、简洁指标、大型搜索、切角筛选标签、聚焦卡片、下一步行动和卡片库。语调变化是有意的：浏览积累材料应感到开阔，而实时 agent 工作应感到受控。

页面保留相同的配色与切角几何，因此仍属于同一产品。适配时应在布局与密度层面保留这种差异，而不是为每项功能发明单独主题。

### 集合、指标与新闻

专家页面使用彩色记录卡、索引数字、头像印章、状态标签和直接操作。监控页面使用更克制的指标语法：卡片、表格化数字、分段计量行、轨迹线和稀疏强调色。新闻使用编辑式图像卡与来源/时间戳元数据。

这些页面展示了一条有用的模式：为任务选择匹配的组件语法。集合可以承受表现性卡片，指标要求更紧凑的系统，信息流需要图像主导的层级。一个万能「卡片」组件会抹平这些差异。

## 响应式模型

| 宽度 | 已观察行为 | 设计意图 |
| --- | --- | --- |
| 大于 1250px | 三栏 Agent 工作台；完整导航轨；三列专家网格。 | 为桌面工作保留持续上下文与可观察性。 |
| 920px 至 1250px | 运行时检查器隐藏；导航轨变窄；Agent 保留上下文与中间列。 | 保护对话，不让它被过度压缩。 |
| 820px 至 920px | 导航轨缩为图标/编号处理；知识库变为单列。 | 在减少导航装饰的同时保留应用方位感。 |
| 820px 及以下 | 侧导航轨消失；汉堡抽屉承载导航和会话；Agent 上下文/检查器隐藏；输入器变为粘性；卡片与消息变为圆角；内容变单列。 | 在触屏上保留任务输入与阅读舒适度。 |
| 430px 及以下 | 标题缩小、输入器更紧凑、单列内容、筛选控件压缩。 | 支持折叠屏外屏和窄手机。 |

最可迁移的响应式规则不是精确断点，而是优先级：先保留当前对话和输入器，把会话与导航工作移入抽屉，并在缩小可读文字或把三栏硬塞进手机之前先移除装饰几何。

## 动效与交互

已观察到的动效克制且状态导向：运行点闪烁、待处理虚线移动、流式光标、低振幅 skeleton 不透明度变化、toast 进入、图像悬停缩放和硬阴影按压反馈。多数转场为约 0.14 至 0.25 秒。界面没有大范围视差、页面切换表演或持续环境动画。

源码包含动画关键帧，但所分析的 CSS 中没有 `prefers-reduced-motion` 覆盖。DSH 适配必须补上这一规则。当用户请求减少动态效果时，闪烁、光标运动、skeleton 闪烁和装饰转场应停止或立即完成。移除动效后，运行时状态仍必须由文字和颜色表达。

## 形成 Boujoy 效果的因素

1. 将本地 AI 工作视为实体工坊，而不是玻璃质感的云端仪表板。
2. 使用暖白色和带色调的黑色，让高饱和颜色看起来像印刷品而非合成霓虹。
3. 使用一个主操作色，并把其余亮色保留给已定义的状态或结构角色。
4. 让三种字体角色划分品牌识别、机器元数据和可读正文。
5. 将切角几何、旋转和硬阴影作为少量可重复的信号，而非随机装饰。
6. 让每个应用模式拥有不同的密度和布局，同时保持配色与控件物理感一致。
7. 让实时 transcript 比启动、停止或中断工作的控件更安静。
8. 移动端应简化而不是缩小。

## Neonforge 的适配护栏

### 应当做

- 应当保留 [Neonforge 参考](neonforge-ui.md) 中的深色本地控制室氛围、可读暖色文字、酸绿操作色、青色健康状态、洋红危险状态和蓝色偏移处理。
- 应当保留 DSH 现有的布局所有权、slot 图、会话数据、运行时行为和组件 API。本文是样式与构图参考，不是移植 Boujoy HTML 或应用模型的理由。
- 应当只在能澄清选中、主要操作、状态变化或功能身份的地方使用切角票券、印章式标记和硬阴影。
- 应当让工具调用、中断、队列和审批在结构上区别于用户和 assistant 正文。
- 应当使用操作、选中、成功、警告、危险、画布、表面和边框等语义别名，而不是在每个组件中导入页面专属颜色名。
- 应当保留清晰焦点指示器、状态点旁的文字标签、键盘访问、触控目标、长文本换行和窄屏退出路径。
- 应当在主题引入闪烁、skeleton 动效、光标动画或动画偏移时，为 `prefers-reduced-motion` 添加覆盖。

### 不应当做

- 不应当复制 Boujoy 的品牌标志、名称、资源文件、FusionPixel 字体文件、截图、产品文案或专有用户内容。
- 不应当在每个屏幕使用全部强调色。Acid、Blue、Pink、Cyan 和 Yellow 必须具备明确的语义角色，否则工作台会产生视觉歧义。
- 不应当让所有卡片都带切角、旋转和阴影。密集工具日志、列表和长对话需要安静表面。
- 不应当只为保留终端美学就把元数据降到不可读的桌面或移动端字号。
- 不应当仅用一个颜色点表达 agent 状态、权限风险或破坏性操作。
- 不应当在它降低输入、阅读或选择舒适度时，把桌面的硬边几何保留到触屏上。
- 不应当把本参考中的装饰文本条、页面编号或拼贴主题变成产品关键导航或状态信息。

## 建议的实现顺序

1. 在 DSH 主题层建立语义颜色、字体、间距、边框、切角、阴影、动效和 z-index token。
2. 将外壳处理应用到既有布局框架：画布、导航轨、分隔线、顶栏和折叠状态。
3. 将对话和输入器重塑为主要操作表面，覆盖空状态、流式状态、排队状态、中断状态、错误状态和附件状态。
4. 以紧凑状态语义加入检查器与工具结果处理，而不是广泛使用装饰卡片。
5. 为知识库、集合、监控和信息流页面应用与任务相称的组件语法。
6. 在扩大主题范围前，验证键盘焦点、对比度、减少动态效果、窄屏布局、长内容、空数据、流式更新、错误和插件 CSS 隔离。

## 已实现的 DSH 适配：当前会话任务票券

第一项已实现的导航处理刻意保持窄范围：既有工作区浏览器中的当前 DSH 会话行会成为不规则裁切的任务票券。左侧任务队列刻意留出更充裕的空间：普通会话票券的最小高度为 48px，方便快速扫读并提供可靠的指针目标；当前票券增至 58px。它组合操作酸绿填充、蓝色 6px × 5px 偏移硬阴影、轻微横向偏移和非矩形轮廓。该行仍保留 `aria-selected`，因此视觉强调是对树形控件当前状态语义的补充，而不是替代。

主题只针对工作区浏览器和会话行自有的 `data-neonforge-*` 钩子。会话选择、排序、菜单、悬浮卡、导航轨折叠和响应式列行为继续由原有 DSH 组件负责。未选中行保持安静；侧栏增加低对比点阵以建立本地控制室语境，但不与对话内容竞争。

## 已实现的 DSH 适配：可读的输入框与操作按钮

输入框现在沿用任务票券的“不透明油墨”系统。深色表面使用青色细描边和克制的蓝色偏移印刷阴影；获得焦点时描边切换为酸绿色，让键盘用户可以快速定位书写区域，而不是依赖弥散光晕。文本区正文使用略带暖色的浅色油墨（`#dbe8e5`），光标使用行动酸绿；占位符和提示文字使用统一的弱化色（`#8fa3a6`），不再使用难以阅读的低对比度白色。

添加和权限控件使用凸起的深色油墨、四像素圆角和青色悬停反馈。发送按钮使用荧光酸绿色填充、深色图标与蓝色偏移阴影；停止按钮使用洋红危险色。禁用操作保持不透明，并保留可读的弱化前景色，避免沿用平台默认的褪色透明度。这些覆盖只作用于输入框自己的钩子，不会改变其他插件按钮的语义。

验收以人眼可读为准：在真实 DSH 渲染中检查正文、占位符、聚焦输入框、发送、停止、禁用和窄屏状态。颜色变化本身不构成通过条件；如果人在正常字号下无法分辨文字与底色，就需要继续调整。验收同时保留截图和计算出的前景/背景颜色值。
